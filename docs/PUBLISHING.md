# Publishing checklist

1. Review the complete file set and test report.
2. Confirm lesson-to-video alignment and replace only verified inventory fields.
3. Choose repository visibility and license deliberately. Keep private while unresolved.
4. Create or select the intended GitHub repository; do not overwrite an unrelated project.
5. Commit this source folder, excluding output, `.venv` and `__pycache__`.
6. Run the test suite from a clean checkout and record results.
7. Verify README links and download behavior.
8. Only then place the verified repository URL in public course descriptions.

Git is optional for running these examples. A ZIP without `.git` can be initialized with `git init`, followed by `git add .`, `git diff --cached` and a descriptive first commit. Set the author using your own Git identity. Use the remote URL supplied by your actual repository.
